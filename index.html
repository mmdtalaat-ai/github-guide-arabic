Git & GitHub — الدليل الشامل للمبتدئين

١ Git مقابل GitHub — إيه الفرق؟

GitHub منصة تخزين وإدارة للمشاريع الرقمية — الفكرة بسيطة: بدل ما كل واحد يحتفظ بنسخة من مشروعه على جهازه بس، بيترفع على GitHub، فيبقى محفوظ ومنظم وقابل للمشاركة والتعديل مع آخرين، من غير ما تضيع أي نسخة سابقة منه.

  • حفظ كل نسخة من المشروع: أي تعديل تعمله يُسجَّل، فتقدر ترجع لأي نسخة سابقة في أي وقت
  • العمل الجماعي: أكتر من شخص يقدر يشتغل على نفس المشروع من مكانه، وGitHub يدمج التعديلات بدون ما يضيع شغل حد
  • المشاركة والنشر: تقدر تعرض مشروعك للعالم (Public)، أو تخليه مقفول على فريقك فقط (Private)
  • الأتمتة: تقدر تخلي GitHub ينفذ خطوات تلقائية (زي فحص الكود أو نشر التحديثات) بدون تدخل يدوي

٣ دورة العمل الأساسية لمشروع على GitHub

هكذا يعمل مشروع نموذجي على GitHub، خطوة بخطوة:

  1. إنشاء المشروع (Repository): صاحب الفكرة يفتح مساحة جديدة على GitHub لمشروعه
  2. رفع الملفات الأولى: يضيف الملفات الأساسية (كود، صور، توثيق)
  3. التعديل المستمر: كل مرة يغيّر شيئاً، يحفظ التغيير كـ Commit (لقطة موثقة للتعديل)
  4. التفرع (اختياري): لو حد تاني عايز يجرب تعديل بدون ما يأثر على النسخة الأصلية، يعمل Branch منفصل
  5. الدمج: بعد التأكد من أن التعديل سليم، يتم دمجه (Merge) في النسخة الرئيسية (main)
  6. الاستخدام: أي شخص يقدر يحمّل (Clone) نسخة من المشروع ليستخدمه على جهازه

٦ الأرقام الخضرا والحمرا — معناها إيه؟

اللي بتشوفه أسفل كل سطر في أدوات الذكاء الاصطناعي البرمجية (زي Claude Code أو Cursor أو GitHub Copilot) أو في الـ Terminal العادي بيبدو كده:

+45 -12
▌ workflow-agent.json
+8 -0
▌ config/settings.env
+120 -89
▌ agents/sales-agent.js
الرمز معناه مثال
+45 عدد الأسطر اللي أُضيفت أو تعدّلت في الملف الأداة أضافت 45 سطر جديد
-12 عدد الأسطر اللي اتحذفت أو استُبدلت الأداة شالت 12 سطر قديم
− (ناقص) علامة الفصل بين الرقمين فقط، مش عمليات تجاهلها

ليه الأرقام بتنقص بعد الـ push؟
لأن Git بيضغط (compress) التغييرات ويحسب الـ «delta» الفعلي — الفرق الصافي بين النسخة القديمة والجديدة. اللي بتشوفه قبل الـ push هو العدد الخام. بعد الرفع GitHub بيعرض فقط الأسطر اللي فعلاً تغيرت مقارنة بآخر commit — فالأرقام بتبان أقل لأن الحساب أدق.

٧ امتى توافق وامتى ترفض؟

📋 أداة الذكاء الاصطناعي بتطلب commit — توافق ولا ترفض؟
✓ وافق

— التعديل اللي طلبته أنت بنفسك
— الملفات المذكورة منطقية للتغيير
— رسالة الـ commit واضحة ومحددة
— git status يعرض ملفات متوقعة فقط
— في مرحلة تطوير عادية

✗ ارفض

— ملفات غير متوقعة في git status
— رسالة الـ commit مش واضحة
— أي تعديل على ملفات .env أو secrets
— بعد جلسة عمل لم تراجع فيها الكود
— الأداة بتقترح commit بدون طلب منك

إجابة السؤال الأساسي:
«لو التعديل مسموح فليه أرفض من البداية؟»

الرفض مش عن التعديل نفسه — هو عن التوقيت والسياق. أغلب أدوات الذكاء الاصطناعي البرمجية بتحتاج موافقتك قبل ما تسجّل أي لقطة في تاريخ المشروع (وبعضها بيدّيك خيار تحط قواعد ثابتة ليها متعملش بيها من غير سؤال). لو وافقت على commit وفيه ملفات غلط أو رسالة مش دقيقة — التاريخ بيتسجل ومش ممكن تمحيه من GitHub بسهولة. الـ commit هو «وثيقة رسمية» في سجل المشروع.

لو رفضت — إيه اللي بيحصل؟

لا شيء يضيع. التعديلات موجودة على جهازك (أو السيرفر) لكنها مش مسجّلة في تاريخ Git. الأداة ممكن تعيد نفس العملية أو تكمّل التعديل وبعدين تطلب commit لما تكون مستعد.

لو وافقت على commit غلط — إيه اللي بيحصل؟

اللقطة اتسجلت في التاريخ. ممكن تعملها undo بـ git revert لكنها بتضيف commit جديد. مش نهاية العالم — لكن بيعقّد السجل.

٨ الأمان والحماية — قبل ما تجرب أي مشروع

هل المشاريع آمنة؟
بشكل افتراضي، مجرد فتح صفحة مشروع على GitHub أو قراءة ملفاته لا يشغّل أي شيء على جهازك، سواء كنت على الموبايل أو الديسك توب. الخطر الحقيقي يبدأ فقط لو حمّلت (Clone) المشروع، وثبّته، وشغّلت الكود فعلياً على جهازك. طول ما أنت بتقرأ وتتصفح بس، أنت في أمان مية بالمية.

ملفات التجسس — إزاي تعرفها كغير تقني

  • أسماء ملفات غريبة أو مشفّرة لا تدل على وظيفتها، خصوصاً في مكان غير متوقع للمشروع
  • طلب صلاحيات لا تتناسب مع وظيفة الأداة — مثلاً أداة تحويل صور بتطلب وصول لجهات الاتصال أو الرسائل
  • روابط تحميل خارجية غامضة داخل التعليمات، بدل ما يكون كل شيء داخل صفحة GitHub نفسها
  • حساب المُنشئ نفسه حديث جداً، بدون أي مشاريع أو نشاط سابق، ومشروعه الوحيد فيه طلب صلاحيات واسعة
  • ملفات بامتدادات قابلة للتنفيذ زي .exe أو .sh — لا تحمّلها ولا تشغّلها إلا لو فاهم وظيفتها بالضبط

أوامر Terminal — قاعدة أساسية تحميك دايماً

لا تقم أبداً بنسخ ولصق أي أمر Terminal من مصدر لا تثق فيه دون أن تفهم ماذا يفعل، حتى لو كان مذكوراً داخل README نفسه. تحديداً، خد بالك من:

  • أي أمر يبدأ بـ sudo (بيطلب صلاحيات إدارية كاملة على جهازك)
  • أي أمر بيحمّل ملف من رابط غير معروف وينفذه مباشرة في نفس الوقت
  • أي أمر طويل ومعقد ومش مشروح ليه سطر بسطر

القاعدة الذهبية: لو مش فاهم الأمر بيعمل إيه بالظبط، لا تنفذه — اسأل قبل ما تنفذ.

قبل إضافة أي مشروع جديد مستقبلاً

  1. طبّق الخطوات الستة اللي فوق (README، تاريخ التحديث، Commits، License، Issues)
  2. لو كل شيء مطمئن، وعايز تستخدمه فعلياً على جهازك، اسأل أي مساعد تقني تثق فيه عن خطوات تثبيته المناسبة لمستواك تحديداً — قبل ما تنفذ أي أمر بنفسك

٩ النجوم ⭐ — يعني إيه ومش مقياس جودة

زر الـ Star بجانب أي مشروع له استخدامان مختلفان تماماً، وخلط بينهما هو سبب اللبس:

الاستخداميعني إيه
إشارة مرجعية شخصية (Bookmark)تضغطها عشان تحفظ المشروع في قائمتك الخاصة، لترجع له لاحقاً — بدون أي علاقة بجودته
تقييم فعلي للجودةبعض المستخدمين، خاصة التقنيين، يضغطونها فعلاً كتصويت إعجاب بجودة المشروع بعد تجربته أو فحص كوده

ليه النجوم مش مقياس دقيق للجودة؟
لأن GitHub لا يميّز بين الحالتين أبداً — الرقم اللي تشوفه هو مجموع الاثنين مخلوطين مع بعض. فمشروع ممكن يكون عنده آلاف النجوم لمجرد إنه انتشر وناس كتير حفظته كـ «أرجعله بعدين»، مش لأنه فعلاً أفضل من مشروع تاني عنده نجوم أقل. لو انت ضغطت نجمة على مشروع عشان تحفظه في حسابك، فده تصرف طبيعي مية بالمية، ولا يعني إطلاقاً إنك بتشهد بجودته.

١١ أسئلة شائعة

السؤالالإجابة
هل أحتاج حساباً على GitHub لتصفح المشاريع؟لا، التصفح والقراءة متاحان للجميع. الحساب مطلوب فقط للتفاعل (نجمة، تعليق، رفع مشروع)
هل حسابي الخاص يعني أن كل مشاريعي خاصة تلقائياً؟لا. كل Repository له إعداد مستقل (Public أو Private) من داخل Settings الخاصة به
هل قراءة الكود على الموقع تُشغّله؟لا، القراءة فقط لا تُشغّل أي شيء أبداً
ما الفرق بين Fork وClone؟Fork ينسخ المشروع إلى حسابك على GitHub نفسه. Clone ينزّل نسخة على جهازك الشخصي
هل يمكنني التراجع عن تعديل بعد حفظه؟نعم، بفضل تاريخ الـ Commits تقدر ترجع لأي نسخة سابقة من المشروع
ما معنى مشروع «مفتوح المصدر»؟يعني أن كوده مرئي للجميع، ويمكن لأي شخص فحصه أو المساهمة فيه
كيف أعرف أن مشروعاً موثوق؟لا يوجد مؤشر واحد كافٍ — اجمع بين: النشاط الحديث، عدد المساهمين، جودة التوثيق، ووجود ترخيص واضح
هل الملفات النصية (مثل README) تحمل مخاطر؟لا، الملفات النصية البسيطة (Markdown) لا تنفذ أي كود بحكم كونها نصاً للقراءة فقط
ما الفرق بين Issue وPull Request؟Issue هو بلاغ أو اقتراح. Pull Request هو تعديل فعلي جاهز، مُقترح للدمج في المشروع
هل يمكنني تحويل مشروع Public إلى Private لاحقاً؟نعم، من تبويب Settings داخل المشروع، في أي وقت

الخلاصة والنصائح النهائية

— اقرأ ملف README دائماً قبل استخدام أي مشروع
— لا تحكم على مشروع بعدد نجومه فقط — انظر للنشاط والتوثيق والترخيص
— التصفح والقراءة آمنان دائماً؛ الحذر مطلوب فقط عند تشغيل كود فعلي على جهازك
— تحقق من إعداد الخصوصية (Public/Private) لكل مشروع تنشئه بنفسك من Settings

١٤ حماية حسابك — المصادقة الثنائية

خطوة لا غنى عنها. بدونها، أي حد يعرف باسوردك (لو اتسرّب من موقع تاني بتستخدم نفس الباسورد فيه مثلاً) يقدر يدخل حسابك مباشرة. المصادقة الثنائية (2FA) بتضيف طبقة حماية تانية غير الباسورد — عادة رمز مؤقت من تطبيق على موبايلك.

إزاي تفعّلها

من صفحة حسابك: Settings ← Password and authentication ← Two-factor authentication ← فعّلها واتبع الخطوات على الشاشة.

قاعدة ذهبية: وقت التفعيل، GitHub هيديك مجموعة Recovery Codes (أكواد استرداد). احتفظ بيها في مكان آمن جداً بعيد عن جهازك أو موبايلك — لو فقدت الموبايل وماكنتش محتفظ بيها، ممكن تفقد الوصول لحسابك للأبد.

١٥ تثبيت Git على جهازك وربط الترمينال بحسابك

لحد دلوقتي كل اللي شرحناه بيتم من المتصفح مباشرة. لو حبيت تشتغل زي المحترفين (رفع وتعديل بسرعة من الترمينال)، محتاج تثبت Git على جهازك الأول:

النظامالخطوات
macOSافتح Terminal واستخدم أداة Homebrew بكتابة الأمر: brew install git
Windowsروح للموقع الرسمي وابحث عن Git for Windows، حمّل الملف التنفيذي وثبّته بالطريقة المعتادة

ربط الجهاز بهويتك

بعد التثبيت، Git لازم يعرف مين انت — افتح موجّه الأوامر واكتب:

git config --global user.name "اسمك"
git config --global user.email "بريدك@example.com"

انتبه: لازم يكون الإيميل هنا هو نفسه الإيميل المرتبط بحسابك على GitHub بالظبط. ده اللي بيضمن ظهور مساهماتك (المربعات الخضرا) بشكل صحيح على بروفايلك.

١٦ أدوات بديلة تسهّل حياتك — بلا أوامر معقدة

مش لازم تشتغل بالأوامر النصية دايماً. فيه أدوات بواجهات رسومية بتنفذ نفس الحاجة:

الأداةمناسبة لمين
Terminalللمحترفين اللي عايزين فهم عميق وتحكّم كامل عبر الأوامر النصية
GitHub Desktopواجهة رسومية بسيطة من GitHub نفسها — بتنفذ status/commit/push بضغطة زر بدل كتابة أوامر
VS Codeمحرر أكواد فيه أدوات Git مدمجة جواه مباشرة — تعديل ورفع من نفس الشاشة
ملاحظة: أدوات الذكاء الاصطناعي البرمجية زي Claude Code وCursor وGitHub Copilot بتغطي دور الترمينال بالكامل — بتشتغل بنفس الأوامر دي جواها، وبتوريك الأرقام الخضرا/الحمرا زي ما شرحنا في القسم الخاص بيها. الأدوات اللي فوق دي بديلة لمين عايز يشتغل بنفسه مباشرة بلا مساعد ذكاء اصطناعي.

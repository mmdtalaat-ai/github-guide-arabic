# github-guide-arabic

دليل GitHub الشامل - لغير التقنيين
دليل مبسط لفهم GitHub خطوة بخطوة، بدون خلفية برمجية. كل قسم يشرح الغرض أولاً، ثم التفاصيل.
1. مقدمة عن GitHub
ما هي GitHub؟
GitHub هي منصة تخزين وإدارة للمشاريع الرقمية (أكواد، ملفات، توثيق). الفكرة الأساسية بسيطة: بدل أن يحتفظ كل شخص بنسخة من مشروعه على جهازه فقط، يتم رفعه على GitHub، فيصبح محفوظاً، منظماً، وقابلاً للمشاركة والتعديل مع آخرين دون أن تضيع أي نسخة سابقة منه.
المميزات الأساسية
حفظ كل نسخة من المشروع: أي تعديل تعمله يُسجَّل، فتقدر ترجع لأي نسخة سابقة في أي وقت.
العمل الجماعي: أكثر من شخص يقدر يشتغل على نفس المشروع من مكانه، وGitHub يدمج التعديلات بدون ما يضيع شغل حد.
المشاركة والنشر: تقدر تعرض مشروعك للعالم (Public)، أو تخليه مقفول على فريقك فقط (Private).
الأتمتة: تقدر تخلي GitHub ينفذ خطوات تلقائية (زي فحص الكود أو نشر التحديثات) بدون تدخل يدوي.
2. التبويبات الرئيسية (8 تبويبات)
كل مشروع (Repository) على GitHub بيتقسم لتبويبات، كل واحد له غرض مختلف:
التبويب
الغرض
Code
مكان الملفات الفعلية للمشروع - هنا تشوف وتقرأ المحتوى.
Issues
قائمة المشاكل والطلبات المفتوحة على المشروع (بلاغ عن خطأ، أو اقتراح ميزة).
Pull Requests
طلبات تعديل مُقترحة من أشخاص آخرين على المشروع، بانتظار موافقة صاحبه.
Projects
لوحة تنظيم المهام (زي لوحة Trello) لمتابعة تقدم العمل.
Wiki
صفحات توثيق إضافية يكتبها صاحب المشروع لشرح تفاصيل أعمق.
Discussions
مساحة نقاش عامة بين المستخدمين، غير مرتبطة بمشكلة محددة.
Actions
الأتمتة - خطوات تُنفَّذ تلقائياً (مثل فحص أو نشر) عند حدوث تغيير معين.
Settings
إعدادات المشروع: من له صلاحية الوصول، هل هو Public أم Private، وغيرها.
3. دورة العمل الأساسية
هكذا يعمل مشروع نموذجي على GitHub، خطوة بخطوة:
إنشاء المشروع (Repository): صاحب الفكرة يفتح مساحة جديدة على GitHub لمشروعه.
رفع الملفات الأولى: يضيف الملفات الأساسية (كود، صور، توثيق).
التعديل المستمر: كل مرة يغيّر شيئاً، يحفظ التغيير كـ Commit (لقطة موثقة للتعديل).
التفرع (اختياري): لو حد تاني عايز يجرب تعديل بدون ما يأثر على النسخة الأصلية، يعمل Branch منفصل.
الدمج: بعد التأكد من أن التعديل سليم، يتم دمجه (Merge) في النسخة الرئيسية (main).
الاستخدام: أي شخص يقدر يحمّل (Clone) نسخة من المشروع ليستخدمه على جهازه.
4. المفاهيم المهمة
المصطلح
الشرح المبسط
Repository
المشروع نفسه - المجلد الكامل الذي يحتوي كل ملفاته وتاريخ تعديلاته.
Branch
نسخة موازية من المشروع، تُستخدم للتجربة بدون التأثير على النسخة الأساسية.
Commit
"لقطة" محفوظة لحالة معينة من الملفات، مع رسالة توضح ماذا تغيّر.
Merge
دمج تعديلات من Branch منفصل إلى النسخة الرئيسية للمشروع.
Clone
تحميل نسخة كاملة من المشروع على جهازك الشخصي.
Fork
نسخ مشروع شخص آخر إلى حسابك الخاص، لتعديله بحرية دون التأثير على الأصلي.
Pull Request
طلب رسمي لدمج تعديل اقترحه شخص ما، بانتظار مراجعة وموافقة صاحب المشروع.
Issue
تذكرة لبلاغ عن مشكلة أو اقتراح تحسين على المشروع.
5. الأمان والحماية
هل المشاريع آمنة؟
بشكل افتراضي، مجرد فتح صفحة مشروع على GitHub أو قراءة ملفاته لا يشغّل أي شيء على جهازك، سواء كنت على الموبايل أو الديسك توب. الخطر الحقيقي يبدأ فقط إذا قمت بتحميل (Clone) المشروع، وتثبيته، وتشغيل الكود فعلياً على جهازك. طول ما أنت بتقرأ وتتصفح بس، أنت في أمان مية بالمية.
فحص كامل قبل تثبيت أي مشروع - خطوة بخطوة (وانت غير تقني)
هذا الفحص تقدره تعمله بنفسك على أي مشروع، سواء المشاريع اللي عندك حالياً في قائمة النجوم، أو أي مشروع جديد هتضيفه مستقبلاً:
افتح صفحة المشروع على GitHub، وادخل على تبويب Code.
اقرأ ملف README كاملاً - المشروع المحترم دايماً بيشرح غرضه بوضوح، وبيقولك يعمل إيه بالظبط. لو الشرح غامض أو ناقص، ده أول علامة تحذير.
افحص تاريخ آخر تحديث: يظهر بجانب اسم كل ملف. مشروع لم يُحدَّث من سنين طويلة، ولا رد صاحبه على أي حد، مؤشر إنه مهجور - وده بحد ذاته خطر لأنه لو فيه ثغرة أمنية محدش بيصلحها.
ادخل على تبويب Commits: هيوريك سجل كل التعديلات اللي حصلت. لو فيه نشاط منتظم من أكتر من شخص على مدار وقت طويل، ده مؤشر ثقة. لو التعديلات كلها من شخص واحد، ومفاجئة، وقريبة من بعض، خد وقتك أكتر قبل ما تثق.
ابحث عن ملف License: المشاريع الجادة عادة بيكون ليها ترخيص واضح ظاهر في الصفحة الرئيسية. غيابه مش دليل خطر لوحده، لكنه مؤشر إضافي على مدى جدية المشروع.
راجع تبويب Issues: شوف هل فيه ناس بلغت عن مشاكل أمان، وهل صاحب المشروع بيرد عليها ولا بيتجاهلها؟
ملفات التجسس - إزاي تعرفها كغير تقني
من غير ما تفهم الكود نفسه، ركّز على العلامات دي:
أسماء ملفات غريبة أو مشفّرة لا تدل على وظيفتها، خصوصاً لو موجودة في مكان غير متوقع للمشروع.
طلب صلاحيات لا تتناسب مع وظيفة الأداة - مثلاً أداة تحويل صور بتطلب وصول لجهات الاتصال أو الرسائل، ده غير منطقي ومؤشر خطر واضح.
روابط تحميل خارجية غامضة داخل التعليمات، بدل ما يكون كل شيء داخل صفحة GitHub نفسها.
حساب المُنشئ نفسه حديث جداً، بدون أي مشاريع أو نشاط سابق، ومشروعه الوحيد فيه طلب صلاحيات واسعة - خد وقتك.
أوامر Terminal - قاعدة أساسية تحميك دايماً
لا تقم أبداً بنسخ ولصق أي أمر Terminal من مصدر لا تثق فيه دون أن تفهم ماذا يفعل، حتى لو كان مذكوراً داخل README نفسه. تحديداً، خد بالك من:
أي أمر يبدأ بـ sudo (بيطلب صلاحيات إدارية كاملة على جهازك).
أي أمر بيحمّل ملف من رابط غير معروف وينفذه مباشرة في نفس الوقت.
أي أمر طويل ومعقد ومش مشروح ليه سطر بسطر.
القاعدة الذهبية: لو مش فاهم الأمر بيعمل إيه بالظبط، لا تنفذه - اسأل قبل ما تنفذ.
إزاي تتأكد من الأمان قبل إضافة أي مشروع جديد مستقبلاً
كل مرة تفكر تضيف مشروع جديد لقائمتك أو تجربه:
طبّق الخطوات السبع اللي فوق (README، تاريخ التحديث، Commits، License، Issues).
لو كل شيء مطمئن، وعايز تستخدمه فعلياً على جهازك، ابعت اسم المشروع أو رابطه هنا، واطلب فحصه وشرح خطوات تثبيته المناسبة لمستواك تحديداً - قبل ما تنفذ أي أمر بنفسك.
6. شرح النجوم والتقييمات ⭐
ما هي النجوم؟
زر الـ Star بجانب أي مشروع له استخدامان مختلفان تماماً، وخلط بينهما هو سبب اللبس:
إشارة مرجعية شخصية ("Bookmark"): تضغطها عشان تحفظ المشروع في قائمتك الخاصة، لترجع له لاحقاً وقت الحاجة - بدون أي علاقة بجودته.
تقييم فعلي للجودة: بعض المستخدمين، خاصة التقنيين، يضغطونها فعلاً كتصويت إعجاب بجودة المشروع بعد تجربته أو فحص كوده.
ليه النجوم مش مقياس دقيق للجودة؟
لأن GitHub لا يميّز بين الحالتين أبداً - الرقم اللي تشوفه (مثلاً "1.2k نجمة") هو مجموع الاثنين مخلوطين مع بعض. فمشروع ممكن يكون عنده آلاف النجوم لمجرد إنه انتشر وناس كتير حفظته كـ "أرجعله بعدين"، مش لأنه فعلاً أفضل أو أأمن من مشروع تاني عنده نجوم أقل. إنت شخصياً لو ضغطت نجمة على مشروع عشان تحفظه في حسابك، فده تصرف طبيعي مية بالمية، ولا يعني إطلاقاً إنك بتشهد بجودته - ومحدش هيفهمها كده غيرك.
النتيجة العملية: لا تحكم على أي مشروع بعدد نجومه وحده، سواء وانت بتقيّم مشروع حد تاني، أو وانت بتفتكر إنت ليه ضغطت نجمة على مشروع معين.
إزاي تعرف إن المشروع "قوي" فعلاً - شرح تفصيلي
بدل النجوم، اعتمد على خمس نقاط، كل واحدة تفحصها في دقيقة من داخل صفحة المشروع نفسها:
1. تاريخ آخر تحديث
افتح تبويب Code، وشوف تاريخ آخر تعديل بجانب الملفات. لو آخر تحديث كان من شهور قليلة، ده مؤشر إن المشروع لسه حي ومتابَع. لو من سنين، يبقى مهجور - حتى لو عنده آلاف النجوم.
2. عدد المساهمين النشطين، مش عدد النجوم
ادخل على تبويب Commits أو ابحث عن قسم Contributors في الصفحة الرئيسية. مشروع بيشتغل عليه أكتر من شخص بانتظام أقوى بكتير من مشروع عنده نجوم كتير لكن صاحبه الوحيد مختفي من سنة.
3. جودة وتفصيل ملف README
مشروع قوي بيشرح نفسه كويس: إيه هو، إزاي تستخدمه، إيه المتطلبات. لو الملف فاضي أو ناقص (زي حالتك انت دلوقتي في الريبو بتاعتك)، ده مؤشر ضعف بغض النظر عن أي حاجة تانية.
4. عدد الـ Issues المفتوحة وسرعة الرد عليها
افتح تبويب Issues. مشروع صاحبه بيرد على المشاكل ويحلها، حتى لو فيه Issues كتير، أقوى من مشروع مفيش فيه أي تفاعل من صاحبه خالص.
5. وجود ملف License واضح
مؤشر إضافي على جدية المشروع والتزامه بقواعد واضحة للاستخدام.
القاعدة الذهبية: لو النقط الخمس دي كويسة، المشروع قوي فعلاً، بغض النظر عن عدد النجوم. ولو النجوم عالية لكن النقط دي ضعيفة، خد حذرك.
مثال عملي
مشروع مثل PDFCraft (أداة مجانية مفتوحة المصدر لمعالجة ملفات PDF) يُقيَّم بالنظر إلى تحديثاته المتكررة، ووجود توثيق واضح، ووجود ترخيص معلن - وليس فقط بعدد نجومه.
7. كيفية استخدام المشاريع
خطوات عملية
اقرأ ملف README أولاً بالكامل - هو دليل الاستخدام.
تحقق من المتطلبات المذكورة (أحياناً يحتاج المشروع برامج معينة مثبتة مسبقاً).
حمّل المشروع (Clone) أو نزّل نسخة مضغوطة منه إذا لم يكن لديك حساب GitHub.
اتبع خطوات التشغيل المذكورة في README بالترتيب.
مثال عملي: PDFCraft
مشروع PDFCraft (أداة تعديل ملفات PDF مفتوحة المصدر) يوضح فكرة الاستخدام: يوفر ملف README يشرح كيفية تحميله محلياً وتشغيله، بدون الحاجة لرفع ملفاتك الشخصية لأي خادم خارجي - وهذا مثال جيد على مشروع يشرح بوضوح غرضه وطريقة استخدامه الآمنة.
8. أسئلة شائعة
1. هل أحتاج حساباً على GitHub لتصفح المشاريع؟
لا، التصفح والقراءة متاحان للجميع. الحساب مطلوب فقط للتفاعل (نجمة، تعليق، رفع مشروع).
2. هل حسابي الخاص يعني أن كل مشاريعي خاصة تلقائياً؟
لا. خصوصية الحساب لا تتحكم في خصوصية كل مشروع على حدة - كل Repository له إعداد مستقل (Public أو Private) من داخل Settings الخاصة به.
3. هل قراءة الكود على الموقع تُشغّله؟
لا، القراءة فقط لا تُشغّل أي شيء أبداً.
4. ما الفرق بين Fork وClone؟
Fork ينسخ المشروع إلى حسابك على GitHub نفسه. Clone ينزّل نسخة على جهازك الشخصي.
5. هل يمكنني التراجع عن تعديل بعد حفظه؟
نعم، بفضل تاريخ الـ Commits تقدر ترجع لأي نسخة سابقة من المشروع.
6. ما معنى مشروع "مفتوح المصدر"؟
يعني أن كوده مرئي للجميع، ويمكن لأي شخص فحصه أو المساهمة فيه.
7. كيف أعرف أن مشروعاً موثوق؟
لا يوجد مؤشر واحد كافٍ - اجمع بين: النشاط الحديث، عدد المساهمين، جودة التوثيق، ووجود ترخيص واضح.
8. هل الملفات النصية (مثل README) تحمل مخاطر؟
لا، الملفات النصية البسيطة (Markdown) لا تنفذ أي كود بحكم كونها نصاً للقراءة فقط.
9. ما الفرق بين Issue وPull Request؟
Issue هو بلاغ أو اقتراح. Pull Request هو تعديل فعلي جاهز، مُقترح للدمج في المشروع.
10. هل يمكنني تحويل مشروع Public إلى Private لاحقاً؟
نعم، من تبويب Settings داخل المشروع، في أي وقت.
9. الخلاصة والنصائح النهائية
اقرأ ملف README دائماً قبل استخدام أي مشروع.
لا تحكم على مشروع بعدد نجومه فقط - انظر للنشاط والتوثيق والترخيص.
التصفح والقراءة آمنان دائماً؛ الحذر مطلوب فقط عند تشغيل كود فعلي على جهازك.
تحقق من إعداد الخصوصية (Public/Private) لكل مشروع تنشئه بنفسك من Settings.
